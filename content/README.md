# 포트폴리오 콘텐츠

노션의 ‘포트폴리오 정리’와 연결된 프로젝트 문서를 바탕으로 작성한 MDX 초안이다. 작성일은 2026-09-16이다. 노션에 정리된 기여 근거를 재구성했으며, 이번 작업에서 회사 저장소·PR·운영 시스템을 직접 재검증한 것은 아니다.

## 파일 구성

- `about.mdx`: 메인·소개 페이지에 사용할 소개와 핵심 역량.
- `projects/shopping-platform.mdx`: 상가 프론트엔드·백엔드 요약 및 모듈별 기록을 하나의 프로젝트로 통합.
- `projects/environmental-health-platform.mdx`: 환경보건 웹·관리자·수집·결측 메일 모듈을 통합.
- `projects/nursery-environment-monitoring.mdx`: 어린이집 환경 모니터링 개선.
- `projects/corporate-website.mdx`: 기업 홈페이지·온라인 채용.
- `projects/corporate-admin.mdx`: 기업 운영 관리자 시스템.

## 작성 기준

- 프로젝트 개요 → 모듈별 요약 → 주요 작업 → 상세 내용 및 설계 자료 순서로 작성한다.
- 주요 작업은 문제·고려사항·담당 작업·기술적 접근·결과로 정리한다.
- 주요 사례는 노션 요약과 상세 기록에서 확인한 기능을 사용한다. 모든 커밋·PR을 옮긴 작업 목록은 아니다.
- 원본의 회사·고객·서비스 식별자, 내부 URL·API 경로·서버 정보·소스 코드·커밋 해시는 공개 콘텐츠에 복사하지 않는다.
- 기록상 기간은 커밋이 확인되는 범위다. 실제 참여·재직 기간, 연속 투입, 팀 규모와 기여율을 추정하지 않는다.
- 원본에 명시된 구현 범위의 숫자와 성과 지표를 구분한다. 운영 효과의 개선율은 만들지 않는다.
- 회사별 소속 관계가 확인되지 않아 `company`와 `companySlug`는 `null`이다. 회사 경력 MDX는 생성하지 않았다.
- 앱인토스와 포트폴리오 자체 프로젝트는 이번 노션 자료에 해당 작업 근거가 없어 생성하지 않았다.

## 메타데이터와 렌더링 계약

프로젝트 공통 필드는 `title`, `slug`, `summary`, `category`, `company`, `companySlug`, `period`, `periodBasis`, `visibility`, `status`, `role`, `technologies`, `modules`, `highlights`다. 파일명과 slug는 일치시킨다.

`status: draft`는 편집 중인 초안이다. `visibility: anonymized`는 익명화 방식이며, 공개 승인이 완료되었다는 의미가 아니다. 발행 구현 시 `status: published`이고 `visibility`가 `private`이 아닌 콘텐츠만 목록·상세 경로·사이트맵·검색 데이터에 포함한다. `restricted`는 메타데이터만 바꾸지 말고 개요·담당 범위만 남도록 본문도 편집한다.

본문은 기본 Markdown과 HTML `details`·`summary`만 사용한다. 별도 커스텀 컴포넌트 없이 상세 내용을 기본 접힘으로 표현한다. 제목은 문서에 H1이 있으므로 페이지 템플릿에서 중복 출력하지 않는다. 소개 파일은 프로젝트 스키마와 분리해서 읽는다.

현재 저장소에는 MDX 렌더링 설정과 콘텐츠 라우트가 없다. 이번 작업은 콘텐츠 작성 범위이며 웹페이지 연결은 포함하지 않는다. Next.js 내장 문서에 따르면 `@next/mdx`는 YAML frontmatter를 기본 지원하지 않으므로 렌더링 구현 시 frontmatter 파서 또는 관련 remark 플러그인을 설정해야 한다. `details` 내부 Markdown이 정상 렌더링되는지도 실제 페이지에서 확인한다.

## 공개 전 보완할 정보

1. 이름·한 줄 소개의 최종 표현과 공개 연락처.
2. 실제 회사별 소속·재직 기간, 프로젝트 참여 기간 및 공식 역할.
3. 각 프로젝트의 익명화 수준과 기술적 상세 내용의 공개 가능 범위.
4. 공개 가능한 화면·설계 이미지와 대체 텍스트.
5. 운영 반영 결과나 측정 자료가 있을 경우 근거를 확인한 성과 표현.

위 정보가 없어도 현재 초안은 검토할 수 있다. 미확인 값을 임의로 채우거나 원본 자료를 자동 공개하지 않는다.

## Work 화면 연결 (2026-09-17)

- `/work`: (주)엔씨엘 경력 요약. 사용자 확인 재직 기간은 2023.07–2026.09이며 소속·공식 직책은 미확정으로 생략한다.
- `/work/projects/[slug]`: 프로젝트별 MDX 본문. 현재 5개 문서는 엔씨엘 경력으로 연결한다. 기존 frontmatter의 회사 필드는 유지하며 이후 데이터 모델 정리 시 갱신한다.
- `features/work/WorkSidebar.tsx`: 회사/프로젝트 2단계 탐색. 회사 정보는 코드에 두고 프로젝트 제목·주소는 조회 결과를 사용한다.
- `lib/content/projects.tsx`: 저장소 안의 신뢰된 MDX만 `next-mdx-remote/rsc`로 처리한다. 서버에서 frontmatter와 본문을 읽으며 클라이언트에 파일 접근 코드를 전달하지 않는다.
- 개발 서버에서는 `draft`도 미리보기로 표시한다. production에서는 `published` 문서만 목록과 상세에 노출한다. `private`는 항상 제외하며 알 수 없는 상태·공개 등급도 제외한다.
- 현재 모든 프로젝트가 초안이므로 production의 프로젝트 목록은 비어 있는 것이 정상이다. 공개 검토를 마친 문서만 `status: published`로 변경한다.
- 템플릿에서 H1을 표시하므로 MDX의 중복 H1은 렌더링하지 않는다. 나머지 본문과 기존 details는 유지한다.
- 이미지 파일은 `public/projects/`에 두고 MDX에 경로와 대체 텍스트를 추가할 수 있다.
- `node scripts/check-work.mjs`: 실행 중인 개발 서버의 5개 문서, 단일 H1, details 내부 목록과 404를 확인한다.
- `node scripts/check-work.mjs http://127.0.0.1:3002 --production`: 현재 초안 문서의 production 비노출을 확인한다. 발행 문서가 생기면 이 검증의 기대값도 갱신한다.

위 설명은 이전의 'MDX 렌더링 설정과 콘텐츠 라우트가 없다'는 작성 시점 설명을 대체한다.
