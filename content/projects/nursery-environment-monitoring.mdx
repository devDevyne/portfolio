# 어린이집 환경 모니터링

어린이집의 실내·실외 환경정보를 조회하고 센서를 관리하는 기존 웹 플랫폼에서 백엔드와 관리자 화면, DID 표시 로직을 개선했습니다. 센서 데이터가 없을 때의 대체 조회와 장비 변경 이력, 최근 수신 상태를 확인하는 기능을 담당했습니다.

- **담당 역할:** Java 백엔드, MyBatis SQL, JSP 관리자 화면 및 DID 데이터 표시 개선.
- **기록상 작업 기간:** 2024.08–2025.03. 실제 연속 투입 기간과는 구분합니다.
- **공개 범위:** 고객·지역·서비스명은 익명화했습니다.

## 프로젝트 개요

센서의 결측과 장비 변경은 화면에 표시할 데이터뿐 아니라 운영자가 상황을 파악하는 방식에도 영향을 줍니다. 저는 기존 플랫폼에서 대체 데이터 조회, 변경 이력 추적, 수신 상태 표시와 검색·다운로드를 보완했습니다.

## 모듈별 요약

- **환경정보 API·DID:** 매핑된 국가측정망, 지역별 측정망, 메인·서브 센서를 활용하는 경로별 대체 조회.
- **센서 이력 관리:** 변경 전 정보 저장, 변경 유형·시각·비고 기록, 기간 검색과 이력 다운로드.
- **수신 상태·현황 조회:** 최근 데이터 등록 여부 표시, 시설별 최신 수신 SQL 개선.
- **검색·Excel 출력:** 센서 타입 조건, 측정·등록 시각 구분, 미가동 센서의 과거 기록 조회.

## 주요 작업

### 1. 결측 조건과 대체 데이터 경로 보완

**문제:** 사설 센서 데이터가 없거나 미세먼지 값이 결측이면 API와 DID에서 제공할 환경정보가 부족했습니다. 대체 측정망에도 값이 없는 경우를 고려해야 했습니다.

**고려사항:** API, 지역 지도, 메인 화면은 기존 데이터 연결 방식이 달라 각 경로에 맞는 대체 순서가 필요했습니다.

**담당 작업:** 센서 목록 API의 국가측정망 매핑과 DID 지도·메인 화면의 대체 조회를 구현했습니다.

**기술적 접근:** API는 매핑된 국가측정망을 조회하고, 지도는 지역별 국가측정망과 추가 예비 데이터를 확인하도록 했습니다. 메인 화면은 메인 센서 결과가 없을 때 서브 센서를 확인하고, 서브 센서 결과도 없으면 유효한 미세먼지 값이 있는 추가 데이터를 조회하도록 보완했습니다.

**결과:** 화면별 결측 조건에 따라 대체 값이 존재하면 환경정보를 표시할 수 있도록 처리 범위를 확장했습니다.

<summary>대체 데이터 해석 범위</summary>

API의 매핑 조회, 지도의 지역별 대체, 메인 화면의 메인·서브 센서 조회는 별도 경로입니다. 메인 화면의 마지막 대체 조회는 국가측정망으로만 제한된 쿼리가 아니므로 모든 대체 값을 국가측정망 값으로 설명하지 않습니다.

대체 값은 원래 센서가 정상 수신했다는 의미와 구분합니다.

### 2. 센서 변경·삭제 이력 관리

**문제:** 센서 식별자와 가동 상태를 변경하거나 삭제한 뒤 이전 정보를 확인할 기능이 필요했습니다.

**고려사항:** 현재 센서 정보와 변경 이전 정보를 구분하고, 운영자가 변경 시점과 유형을 검색할 수 있어야 했습니다.

**담당 작업:** 변경·삭제 전 정보를 이력으로 저장하고 이력 목록, 기간 검색, Excel 다운로드를 연결했습니다.

**기술적 접근:** 최초 등록 시각, 변경·삭제 시각, 변경 유형과 비고를 저장하도록 매핑을 확장했습니다. 등록·수정 화면에는 센서 ID 중복 확인 요청과 가동 상태 선택을 추가했습니다.

**결과:** 장비의 현재 정보와 과거 변경·삭제 내역을 관리자 화면에서 추적하도록 구성했습니다.

### 3. 수신 상태 표시와 최신 내역 SQL 개선

**문제:** 센서 이름만으로 최근 데이터 수신 여부를 파악하기 어려웠으며, 시설 현황의 최신 수신 조회에는 풀스캔 문제가 기록되어 있었습니다.

**고려사항:** 수신 여부는 최근 등록된 데이터 행의 존재로 판단하고, 시설별 최신 시각과 해당 시설을 함께 조건으로 조회해야 했습니다.

**담당 작업:** 최근 3시간 내 데이터 등록 여부를 메인·서브 센서 선택 목록과 시설 목록에 표시했습니다. 최신 수신 내역 조회 SQL도 수정했습니다.

**기술적 접근:** 최신 시각을 찾던 IN 서브쿼리를 시설명별 최신 등록 시각 집계 결과와의 JOIN으로 변경하고 관련 인덱스를 활용하도록 구성했습니다.

**결과:** 센서 선택과 연결 정보 확인 시 최근 수신 여부를 함께 볼 수 있게 하고, 시설별 최신 수신 조회 구조를 개선했습니다. 수신 표시는 모든 측정 항목의 정상값 여부와는 구분합니다.

### 4. 과거 데이터 조회와 업무 자료 출력 개선

**문제:** 현재 미가동인 센서의 과거 기록을 조회하고, 화면의 검색 조건과 시간 정보를 Excel에서도 확인할 필요가 있었습니다.

**고려사항:** 현재 장비 상태와 과거 측정 이력을 구분하고, 실제 측정 시각과 시스템 등록 시각을 함께 제공해야 했습니다.

**담당 작업:** 미가동 센서 조회 조건, 센서 타입 검색, 측정·등록 시각 표시 및 Excel 출력을 보완했습니다.

**기술적 접근:** 목록·건수·다운로드 SQL에 검색 조건을 연결하고 센서 연결 정보·가동 상태·변경 이력을 출력 항목에 반영했습니다.

**결과:** 운영자가 조회한 조건에 맞춰 과거 환경정보와 장비 이력을 업무 자료로 내려받도록 개선했습니다.

## 상세 내용 및 설계 자료

기존 플랫폼의 기능 확장·개선 범위를 다뤘으며 전체 플랫폼 신규 구축이나 외부 API 수집기 최초 개발로 표현하지 않았습니다. SQL 개선의 전후 실행 계획·응답 시간 자료는 확인되지 않아 성능 향상률을 기재하지 않았습니다.
