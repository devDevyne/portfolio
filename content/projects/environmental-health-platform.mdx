# 환경보건 데이터 플랫폼

기존 환경보건 플랫폼의 수집·저장·집계와 웹 조회 기능을 확장하고, 실내공기질 모니터링·통계 모듈을 개발했습니다. 관리자 설정부터 정기 수집, 결측 이력, 차트·지도·보고서까지 데이터가 전달되는 여러 계층을 수정했습니다.

- **담당 역할:** Java/Spring 백엔드, SQL, JSP·JavaScript 화면, 스케줄러 기능 개발·유지보수.
- **기록상 작업 기간:** 2024.08–2026.03. 모듈별 개발 기록과 후속 유지보수를 합친 범위이며 연속 투입 기간을 뜻하지 않습니다.
- **공개 범위:** 서비스·고객·지역 식별 정보는 익명화했습니다.

## 프로젝트 개요

지역과 측정기마다 제공하는 항목이 달랐고, 수신 시각 오류나 결측 데이터를 운영자가 확인할 수 있는 처리도 필요했습니다. 저는 기존 시스템의 수집·집계 경로를 확장하고, 저장된 측정값과 결측 이력을 화면과 보고서에서 확인할 수 있는 기능을 개발했습니다.

## 모듈별 요약

- **데이터 수집·집계:** 신규 물질 파싱·저장, 기간별 평균 쿼리, 시각 오류 대응, 실내공기질 일일 집계.
- **실내공기질 모니터링:** 측정현황, 실측·결측 조회, 시간대별 목록과 센서별 최근 유효값 조회.
- **통계·지도·다운로드:** 물질·시설군·시설·월별 통계, 국가측정망 비교, 농도 지도, Excel·그래프 ZIP 출력.
- **결측 이력·메일 보고:** 수신 지역별 보고, 결측 구간 저장, 평일 발송 정책, HTML 캘린더와 첨부 보고서.
- **측정망·수신자 관리:** 국가측정망 지역 연결, 수신자별 복수 지역 및 시간 옵션, 수집서버 지역 식별자 관리.

## 주요 작업

### 1. 신규 측정항목과 집계 경로 확장

**문제:** 지역·센서가 추가되면서 기존 항목 외에 황화수소·암모니아·라돈을 처리해야 했습니다.

**고려사항:** API 응답의 필드 추가만으로는 충분하지 않았으며, 데이터 모델·저장·집계·화면·출력에 같은 항목이 반영되어야 했습니다.

**담당 작업:** 지역별 파싱 조건, 데이터 모델, 저장 SQL과 10분·시간·일·주 평균 쿼리를 확장했습니다. 실내공기질 시간별 데이터의 9개 항목을 센서별 일일 평균으로 저장하는 정기 집계도 추가했습니다.

**기술적 접근:** 지역별 항목 차이를 파싱·SQL 분기에 반영하고, 신규 지역의 초기 집계 시작 시각을 10분·시간·일 단위에 맞춰 정렬했습니다. 웹에서는 컬럼 메타데이터와 지역·실내외 조건을 조회·표시·다운로드에 전달했습니다.

**결과:** 신규 항목을 수집부터 기간별 집계와 조회·출력까지 연결하고, 별도의 일일 집계 경로를 구현했습니다.

### 2. 외부 데이터 시각 오류와 수집 지연 대응

**문제:** 특정 지역의 실내 센서에서 데이터 날짜가 다음 날이나 이전 날로 전달되는 문제가 있었습니다.

**고려사항:** 외부 응답 시각을 그대로 저장 기준으로 사용하기 어려웠고, 수집 지연을 고려하면서 원본 시각도 남겨야 했습니다.

**담당 작업:** 해당 지역의 수집 흐름을 분리하고 API 연동·파싱 조건을 수정했습니다. 원본 데이터 시각과 플랫폼 저장 시각을 구분하고 등록 시각 기반 재조회 로직을 구현했습니다.

**기술적 접근:** 마지막 DB 등록 시각보다 2분 이전부터 데이터를 조회하고, 마지막 저장 데이터 시각과 기준 시각을 비교해 INSERT 또는 UPDATE하도록 구성했습니다.

**결과:** 조회 기준, 플랫폼 데이터 시각, 원본 응답 시각을 구분해 오류 상황을 처리할 수 있도록 수집 흐름을 보완했습니다. 이 변경의 누락률 감소나 완전한 중복 방지는 별도 측정 성과로 제시하지 않습니다.

### 3. 결측 시간대와 연속 구간을 드러내는 조회

**문제:** 존재하는 측정 행만 조회하면 값이 없는 시간대가 목록에서 빠지고, 시간 단위 결측 기록을 그대로 나열하면 장기간의 상태를 파악하기 어려웠습니다.

**고려사항:** 조회 화면의 빈 시간대 표시와 보고서의 연속 결측 구간 집계는 서로 다른 데이터 가공이 필요했습니다.

**담당 작업:** 실내공기질 모니터링 SQL과 결측 알림용 연속 구간 집계를 구현했습니다.

**기술적 접근:** 재귀 CTE로 시간 슬롯을 생성하고 측정값을 LEFT JOIN해 결측 시간도 행으로 표시했습니다. 알림용 시간 단위 결측 기록에는 `LAG`로 이전 기록을 확인하고 누적 `SUM OVER`로 구간 ID를 생성한 뒤 날짜·센서·구간별로 시작·종료 시각을 집계했습니다.

**결과:** 결측 시간대가 포함된 조회 목록과 같은 날짜 안에서 끊어진 구간을 구분하는 보고 데이터를 제공했습니다.

### 4. 결측 이력 저장과 업무일 보고 자동화

**문제:** 주말 메일 발송을 제한하기 위해 스케줄 실행 자체를 막으면 같은 처리 안의 이력 저장도 실행되지 않는 구조였습니다.

**고려사항:** 이력 축적과 발송 정책을 분리하고, 월요일 보고에는 주말 동안의 기록을 포함해야 했습니다.

**담당 작업:** 결측 이력 저장 후 요일에 따라 발송 여부를 결정하도록 개선했습니다. 수신자별 담당 지역을 적용하고 월요일 조회·표시를 지난 금요일부터의 이력으로 확장했습니다.

**기술적 접근:** 스케줄 실행, 본문 생성, 메일 발송의 책임을 나누었습니다. Thymeleaf로 월간 캘린더·상세 목록을 생성하고 Apache POI로 어제가 속한 월과 이전 두 달의 종일 이력을 3개 시트로 구성해 첨부했습니다.

**결과:** 주말에도 이력을 저장하면서 평일 보고 정책을 적용하고, 월간 현황과 상세 구간·최근 3개월 이력을 함께 확인하는 보고 경로를 구현했습니다.

이력의 보고일자는 메일 작성일이 아닌 결측 시작일을 기준으로 저장하도록 변경했습니다. 분 단위 기록 수는 시작·종료 시점을 포함해 계산하고, 보고 유형별 조회 조건을 적용했습니다.

실내공기질 모듈에는 별도 수신자 조회와 연속 결측 구간 집계·메일 발송 흐름을 추가했습니다. 최근 3개월 Excel 자동 첨부는 기존 환경보건 결측 보고에 구현한 기능이며, 실내공기질 메일에도 완료된 것으로 포함하지 않았습니다.

발송 흐름을 구현한 이력에 대한 설명이며 현재 운영 스케줄의 활성 상태를 뜻하지 않습니다.

### 5. 통계·지도와 그래프 일괄 다운로드

**문제:** 같은 데이터를 물질·시설군·개별 시설·월별 관점으로 비교하고, 시설별 그래프를 파일로 추출할 필요가 있었습니다.

**고려사항:** 통계별 집계 단위와 비교 목적을 맞추고, 여러 시설의 차트를 순서대로 생성하면서 진행 상태와 실패 후 UI를 처리해야 했습니다.

**담당 작업:** 통계 조회·화면과 국가측정망 비교 차트, Google Maps 농도 지도 및 시설별 그래프 다운로드를 개발했습니다.

**기술적 접근:** ApexCharts 인스턴스를 시설별로 갱신하고 PNG를 추출해 JSZip으로 묶었습니다. 지도에는 지역 경계와 농도 색상을 연결하고 조회 시 위치·확대 수준·표시 선택을 전달했습니다.

**결과:** 네 가지 통계 관점과 시설별 비교 차트를 제공하고, 여러 시설의 그래프를 한 번의 다운로드 동작으로 생성·압축하도록 구성했습니다.

## 상세 내용 및 설계 자료

기존 수집·메일 시스템의 확장과 신규 실내공기질 모듈 개발을 구분해 작성했습니다. 센서 펌웨어, 외부 수집 서버 전체, 플랫폼 최초 구축은 이 문서의 담당 범위에 포함하지 않습니다.

작업 기록상 관리자 모듈은 2024.08–2025.06, 수집 모듈은 2024.10–2025.06, 웹 모듈은 2024.10–2025.08, 메일 모듈은 2024.09–2026.03입니다. 실제 화면·보고서 예시는 식별 정보와 운영 데이터를 제거한 뒤 추가할 예정입니다.
