# 기업 운영 관리자 시스템

채용, 임직원·조직, 홈페이지 콘텐츠와 사업 실적을 관리하는 기존 웹 시스템의 개발·유지보수에 참여했습니다. 인증·권한 정책과 관리 화면의 요청을 연결하고, 검색·메일·파일 처리 기능을 개발·개선했습니다.

- **담당 역할:** Java 백엔드, MyBatis SQL, JSP·JavaScript 화면 및 Spring 설정 변경.
- **기록상 작업 기간:** 주요 개발 2024.03–2024.04, 후속 유지보수 2025.05·2026.03.
- **공개 범위:** 고객·회사·서비스명은 익명화했습니다.

## 프로젝트 개요

기존 세션 검사와 메뉴 권한 데이터를 공통 인증·인가 흐름에 연결하고, 업무별로 필요한 검색 조건과 관리자 작업 흐름을 확장했습니다. 이후 환경 변경에 따른 파일 경로 수정과 에디터 이미지 업로드 연동 보완도 수행했습니다.

## 모듈별 요약

- **인증·업무별 접근 권한:** DB 권한 매핑, 로그인 성공·실패 처리, 역할별 URL 정책과 메뉴 표시, CSRF 반영.
- **목록 검색·페이지네이션:** 홈페이지·현장·조직·임직원·실적·채용의 조건 검색과 건수 조회.
- **채용 운영·메일:** 지원자·공고·면접일 조회, 메일 편집·발송, 빈 조회 결과와 잘못된 데이터 연결 보완.
- **파일·에디터 연동:** 유형별 다운로드, 첨부 삭제, 환경 변경에 따른 경로 수정과 이미지 업로드 연결.

## 주요 작업

### 1. 업무별 접근 권한과 화면 요청 연결

**문제:** 기존 컨트롤러의 개별 세션 검사와 DB 메뉴 권한 정보를 인증·접근 정책에 연결할 필요가 있었습니다.

**고려사항:** URL 접근 제어와 화면 메뉴 노출이 같은 권한 정보를 사용하도록 하고, 폼·AJAX 요청에도 보안 설정을 반영해야 했습니다.

**담당 작업:** Spring Security 인증 구성, 로그인 성공·실패 처리, 6개 업무 영역의 역할별 URL 접근 제어와 메뉴 표시를 구현했습니다.

**기술적 접근:** DB 메뉴 권한을 역할로 변환하고 인증 과정에서 BCrypt 비밀번호 검증을 연결했습니다. 주요 입력·삭제 화면의 폼과 AJAX에 CSRF 토큰을 반영하고 여러 삭제 동작을 POST 폼 제출로 변경했습니다.

**결과:** 업무 영역별 접근 정책과 권한별 화면 구성을 연결했습니다. 이 범위가 시스템 전체의 보안 검증 완료를 의미하지는 않습니다.

### 2. 업무별 검색 조건과 페이지네이션 확장

**문제:** 게시판·현장·조직·임직원·사업 실적마다 조회에 필요한 조건이 달랐습니다.

**고려사항:** 목록 SQL과 전체 건수 조회에 같은 조건을 적용하고, 화면의 검색값과 현재 페이지를 함께 전달해야 했습니다.

**담당 작업:** 검색 데이터 객체와 MyBatis 동적 SQL, 기존 페이지 계산 객체, JSP 목록을 연결했습니다.

**기술적 접근:** 제목·내용·현장명·주소·조직명·직원명 등 업무별 조건을 분기하고 목록 제한과 검색 조건을 반영한 COUNT 쿼리를 적용했습니다. 사용 여부 필터와 페이지 활성 표시도 보완했습니다.

**결과:** 관리자가 업무에 맞는 조건으로 목록을 좁히고 페이지 단위로 조회하도록 확장했습니다.

### 3. 채용 결과 메일 작성·발송 흐름 구현

**문제:** 담당자가 지원자와 채용공고 정보를 확인하고 안내 내용을 작성해 발송할 수 있는 화면이 필요했습니다.

**고려사항:** 지원자·공고·면접 정보를 연결하되 담당자가 본문을 편집하고 결과 목록으로 돌아갈 수 있어야 했습니다.

**담당 작업:** 메일 작성용 조회 SQL, SmartEditor2 기반 작성 화면과 기존 메일 모듈 호출을 구현했습니다.

**기술적 접근:** 지원자와 공고를 조인하고 면접 정보를 LEFT JOIN으로 조회했습니다. 수신자·제목·기본 문구를 채운 뒤 담당자가 편집한 본문을 기존 발송 모듈에 전달했습니다.

**결과:** 관리자 화면 안에서 대상 조회, 메일 작성, 발송과 목록 복귀까지 이어지는 흐름을 구성했습니다. 담당자가 실행하는 기능이며 상태 변경에 따른 자동 발송이나 대량 비동기 발송은 포함하지 않습니다.

### 4. 파일 처리와 에디터 이미지 업로드 보완

**문제:** 서버 환경 변경 이후 파일 경로를 조정하고 누락된 에디터 이미지 업로드 연결을 보완해야 했습니다.

**고려사항:** 에디터의 요청 URL·헤더와 서버 저장·응답 형식을 함께 확인해야 했습니다.

**담당 작업:** 공통 다운로드와 첨부 삭제를 연결하고, 후속 유지보수에서 파일 경로 변경 및 에디터 업로드 API를 구현했습니다.

**기술적 접근:** 저장 디렉터리를 생성하고 날짜·UUID 기반 파일명으로 요청 스트림을 저장한 뒤 에디터가 사용하는 이미지 URL을 반환하도록 구성했습니다. 클라이언트 요청 URL과 Content-Type도 수정했습니다.

**결과:** 관리자 파일 입출력과 에디터 이미지 삽입 흐름을 보완했습니다. 이 변경은 기능 연동 사례로 다룹니다.

## 상세 내용 및 설계 자료

기존 채용·Excel·메일 기능 전체를 신규 개발 성과로 포함하지 않고, 확인된 확장·연동·예외 처리 범위로 작성했습니다. 서버 이전 총괄이나 실제 운영 발송 성공·처리 시간 단축에 대한 수치는 포함하지 않았습니다.
